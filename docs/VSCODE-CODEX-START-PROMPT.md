# VS Code Codex 개발 시작 프롬프트

Ubuntu 서버에 Remote SSH로 접속하고 이 저장소를 연 뒤, 해당 워크스페이스의 Codex 대화에 아래 내용을 붙여 넣는다. 이 문서는 구현 지시용이며 완료 보고가 아니다. 기존 로컬 변경이 있다면 보존한 상태에서 시작한다.

```text
이 저장소의 Paper Reader를 VS Code Remote SSH + Codex 환경으로 마이그레이션하기 시작해라.
대상 서버 OS는 Ubuntu 20.04.6 LTS다. PDF를 VS Code에서 읽고, 선택 문장과 적절한 원문 문맥을 내가 지정한 기존 Codex 대화에 전달하고, 답변을 원래 PDF 위치의 노트로 저장하는 것이 목표다.

먼저 적용되는 AGENTS.md와 다음 문서를 읽어라.
- docs/VSCODE-CODEX-MIGRATION.md
- docs/DEVELOPMENT-HANDOFF.md의 최신 항목
- docs/PARAGRAPH-CONTEXT.md
- docs/IMAGE-REUSE.md

이번 작업은 계획의 M0와, 그 결과에 맞는 M1 최소 시제품까지다. 계획을 반복해서 설명하는 데 그치지 말고 환경 조사, 작은 연동 실험, 코드 작성, 검증까지 진행해라.

1. 현재 브랜치·원격·미커밋 변경을 확인하고 기존 작업을 보존해라. 안전한 별도 개발 브랜치에서 진행해라. 최신 원격과 차이가 있으면 먼저 확인하되 강제 reset, 기존 변경 삭제, 무조건적인 pull은 하지 마라. 문서 작성 기준은 0.14.9/344c9d3이지만 이후 변경도 확인해라.
2. OS/CPU/VS Code/Remote SSH/Codex/Node 버전과 실제 프로세스 실행 위치를 확인해라. Ubuntu에 실제 접속했는지 구분하고, 로컬 Windows 검증을 원격 검증으로 보고하지 마라. 기존 테스트의 실행 결과와 환경 때문에 실행하지 못한 항목을 기록해라. 비밀정보나 개인 경로는 공개 메모에 넣지 마라.
3. 첫 실험은 '기존 Codex 대화에 정확한 문맥을 전달할 수 있는가'다. 설치된 Codex 확장과 공식 문서를 확인하고 chatgpt.addToThread/addFileToThread 등 공개 명령을 작은 확장에서 검증해라. PDF Webview 선택과 텍스트 편집기 선택의 차이를 처리해라. 두 대화·두 패널 사이에서 실제 대상과 동작을 확인해라. 자동 전송, 대상 thread ID 확인, 답변 이벤트 수신은 각각 검증하고, 지원된다고 추정하지 마라.
4. 공개 API로 기존 세션 자동 연결이 안 되면 문맥 첨부+사용자 직접 전송을 명확히 표시하는 최소 동작을 제시해라. 새 App Server 대화를 만들었다고 기존 IDE 세션 연결이 됐다고 하지 마라. 별도 App Server 모드로 제품 방향을 바꾸기 전에는 실험 근거와 선택 사항을 보고해라. 독립적인 PDF UI 작업은 계속할 수 있다.
5. M1은 원격 PDF Custom Editor/Webview, 문장 선택, 원문 페이지·앵커를 포함한 질문 문맥, 연결 대상/상태 표시, 질문 초안 보존까지만 작게 구현해라. 확장은 원격 workspace host, UI는 로컬 VS Code라는 경계를 지켜라. 필요하면 단계 2의 서버 접근 정보가 부족한 부분만 질문하고 독립 작업을 계속해라.
6. 기존 문단 검색·짧은 읽기·확장 커서·이미지 재전송·자료 전달 기록·주석 좌표·고정본·백업 복구를 보존해라. Linux 렌더링과 SQLite FTS5/authorizer는 실제 런타임에서 확인해야 한다. 기존 Electron/Windows 동작을 대규모로 옮겨 쓰기 전에 어댑터 경계부터 만들어라.
7. Codex 인증은 표준 흐름을 재사용하고, 인증 파일·키·쿠키를 읽어 문서나 로그에 출력하지 마라. 기존 MCP 설정·노트·공유 데이터는 삭제하지 마라. 비공개 명령, 세션 파일 수정, 채팅 DOM 자동화를 제품 통합 수단으로 삼지 마라.
8. 질문을 보낼 때 문서 고정본·selectionId·요청 ID·확인 가능한 대화 대상을 묶어라. 다른 PDF/패널로 전환하거나 재접속해도 오발송·중복 전송·잘못된 노트 저장을 막아라. MCP 등록만으로 사용자 메시지를 보낼 수 있다고 가정하지 마라.

실제 UI 검증은 이 세션에서 제공되는 내장 Computer Use가 있을 때 그것을 사용해라. 없으면 코드/자동 테스트 결과와 수동 확인이 필요한 항목을 구분하고 UI 성공을 주장하지 마라. NTK 1806.07572v4.pdf가 있으면 선택 발췌와 원문 페이지로 확인하고, 없으면 개인 파일을 임의로 가져오지 말고 필요한 시험 자료만 요청해라.

마무리에는 변경한 코드, 실행한 테스트, 기존 세션 연결의 관측 결과, 미검증 범위, 다음 단계 및 필요한 사용자 조치를 docs/DEVELOPMENT-HANDOFF.md에 기록하고 요약해라. 이번 프롬프트만으로 배포·commit·push하지 마라. 추가 지시가 있으면 따른다.
```
