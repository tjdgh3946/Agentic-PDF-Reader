# 이미지 재사용·영역 확대와 논문 노트 표시 · 0.12.3

## 같은 이미지는 참조로 재사용

`render_pdf_page`는 같은 `selectionId`에서 페이지·영역별로 PNG를 한 번만 반환한다. 기본 영역과 `[0,0,1,1]`은 같다. 좌표는 소수점 네 자리로 정규화해 작은 부동소수점 차이도 같은 요청으로 처리한다.

- 첫 요청: `delivery: image`, `imageReturned: true`, `imageRef`, 메타데이터와 실제 이미지 콘텐츠.
- 반복 요청: `delivery: reference`, `imageReturned: false`, 같은 `imageRef`와 메타데이터만 반환. PNG·base64는 없다. 기존 이미지를 활용하거나 더 작은 영역을 요청하라는 안내가 나온다.
- 동시 반복 요청도 하나로 합친다. 실패한 렌더는 정상 재시도할 수 있고 성공한 이미지의 참조는 실패한 재전송 때문에 사라지지 않는다.
- 추적 정보는 공유별 최대 32개 영역이며 PNG 원본 바이트는 보관하지 않는다. 한도를 넘어 새 영역을 요청하면 새 공유가 필요하다고 안내한다. 이전 참조는 밀어내지 않는다.

새 공유 ID는 다른 대화에서 사용될 수 있으므로 전달 기록을 새로 시작한다. 공유 만료/해제/앱 종료 시 추적 정보도 폐기된다. 이전 ChatGPT 메시지를 삭제하는 기능은 아니다. 서버의 성공 결과 기록은 네트워크 수신을 보장하지 않으므로 아래 재전송 예외를 제공한다.

## 더 자세히 볼 때는 영역 확대

좌표 `[x,y,width,height]`는 **원래 페이지 전체 기준** 0~1이며 PDF 자체 회전을 적용한 왼쪽 위가 원점이다. 직전 잘라낸 이미지 기준이 아니며 사용자 뷰어 회전과도 별개다.

더 작은 영역은 별도의 새 이미지로 반환한다. 기존 PNG를 잘라 늘리는 방식 대신 원본 PDF를 다시 렌더링한다. 영역의 긴 변 최대 2,000px, 전체 페이지 기준 최대 8배 확대다. 크게 확대된 전체 페이지 캔버스를 만들지 않고 필요한 영역 크기의 캔버스에 직접 그린다. 같은 확대 영역을 다시 요청하면 참조만 반환한다.

NTK `1806.07572v4.pdf`의 Figure 3(c)는 페이지 9의 `[0.58,0.08,0.27,0.22]`에서 축·범례·캡션을 함께 읽을 수 있다. 실제 반환은 1,897×2,000px, 전체 페이지 대비 약 4.55배다.

이전 이미지가 오래된 대화 문맥에서 사라졌거나 수신 실패로 보이지 않을 때만 `resend:true`와 구체적 `reason`(최대 180자)을 지정해 다시 받는다. 확대하려는 목적이면 재전송 대신 더 작은 `region`을 지정한다. 이미지 참조만 받은 것을 새로운 이미지 확인으로 표현하지 않도록 도구 지침을 갱신했다.

앱 호출 상태는 **이미지 확인 / 이미지 재사용 / 영역 확대**를 구분한다. ChatGPT 플러그인 **관리 → 도구 새로 고침**으로 MCP 0.3.1의 설명·입력 스키마를 갱신한다.

## 논문 노트에는 내용이 있는 항목만 표시

노트 문자열을 trim한 뒤 내용이 있는 항목만 논문 노트 목록·검색·개수·Markdown 내보내기에 포함한다. AI 저장 답변과 직접 작성한 노트에 같은 기준을 적용한다. 기존 하이라이트 데이터는 삭제하지 않으며 PDF 위 표시도 유지한다.

하이라이트만 저장하면 노트 창이 자동으로 열리지 않는다. PDF의 하이라이트를 클릭하면 편집기가 열려 내용을 추가하거나 하이라이트를 삭제할 수 있다. 내용을 추가하면 목록에 나타나고, 내용을 모두 비우면 다시 하이라이트만 남는다. 노트 아이콘도 실제 내용이 있을 때만 표시한다. MCP `list_annotations`는 이름 그대로 하이라이트를 포함한 기존 주석을 읽을 수 있으며 논문 노트 UI 목록과는 구분된다.

## 0.12.1 당시 검증

- `npm test`: 123개 통과. 동일·동시 요청, 좌표 정규화, 새 영역/공유, 명시적 복구, 실패 후 재시도, 범위 한도·해제, MCP 이미지 콘텐츠 유무와 노트 내용 필터/검색/내보내기를 검증했다.
- `npx electron scripts/pdf-image-reuse-check.mjs <NTK.pdf> <output-directory>`: 실제 PDF.js와 MCP에서 전체 페이지 3회 요청의 이미지 수 `1,0,0`, 확대 영역 2회 요청의 이미지 수 `1,0`, 의도한 복구 요청의 이미지 수 `1`을 확인한다.
- 격리된 내장 브라우저 시험에서 빈 하이라이트 2개와 실제 노트 1개 중 목록·개수에 1개만 표시했다. 내용을 비우면 0개/내보내기 비활성, PDF 하이라이트 클릭 후 다시 내용을 적으면 1개가 되는 것을 확인했다. 사용자 노트는 변경하지 않았다.
- 실제 ChatGPT 웹 호출에서도 전체/확대 요청 4회에 PNG 2개와 참조 2개가 반환됐다. 다만 해당 웹 대화의 모델은 이미지 픽셀을 읽지 못해 시각 판독 검증은 미완료다. 별도의 이 Codex 대화 연결 도구에서는 실제 PNG 이미지 블록을 받아 축·범례·곡선을 읽고, 동일 영역 재요청의 이미지 블록 0개/같은 참조를 확인했다. 일시적 연결 실패 및 웹 경로의 처리 오류를 포함한 [최종 검증 범위](image-reuse-evaluation-0.12.1.json)를 참고한다.

## 0.12.2 당시 우회 (0.12.3에서 제거)

같은 서버·같은 PNG 응답에서 특정 기존 ChatGPT 대화는 메타데이터만 읽고, 새 대화는 실제 픽셀을 읽는 차이를 재현했다. 구조화 결과 필드 제거와 새 이미지 도구 별칭만으로 기존 대화를 복구하지 못했다. 해당 실험 변경은 배포에서 제거했으며, MCP는 표준 이미지 content와 메타데이터 structuredContent를 유지한다. ChatGPT 내부의 정확한 원인은 확인할 수 없으므로 서버 이미지 반환을 모델의 판독 성공으로 단정하지 않는다.

이미지 호출 기록이 생기면 **새 대화로 다시 질문** 버튼이 나타난다. 이 버튼은 현재 PDF와 질문을 새 공유 ID로 만들어 새 ChatGPT 대화에 보낸다. 기존 공유 ID를 새 대화에 그대로 복사하면 이미지 대신 이전 참조가 돌아올 수 있으므로 새 ID가 필요하다. 일반 전송 재시도의 중복 방지는 유지한다. 저장 옵션도 현재 체크박스대로 유지하며 이미 저장된 답변에는 복구 버튼을 표시하지 않는다.

- Windows EXE: 로그인 세션을 유지하고 새 대화 입력창이 준비된 뒤 전송한다. 작성 중인 초안이나 답변 생성 중이면 이동·전송을 중단한다.
- 브라우저 미리보기: **새 대화용 질문 복사**를 누르고 ChatGPT에서 새 대화 → Paper Reader Link 선택 → 붙여넣기·전송한다.
- 기존 ChatGPT 대화는 기록에 남는다. 이전 대화 텍스트는 새 대화로 자동 전달하지 않으며, 기존 PDF 논문 노트는 같은 문서의 MCP 도구로 다시 읽을 수 있다.
- 모델은 실제 픽셀을 확인한 뒤에만 색상·축·범례를 설명해야 한다. 이미지가 없으면 사유를 적어 한 번만 복구 재전송하고, 계속 실패하면 반복 확대 대신 위 버튼을 안내한다.

검증에서는 원본 NTK PDF와 별도로 텍스트 추출에 없는 무작위 코드·색상 표식을 그림 위에 넣은 사본을 사용했다. 모델이 사전에 알려주지 않은 코드와 색상 순서를 정확히 읽어 실제 픽셀 접근을 확인했다. 원본 PDF는 수정하지 않았다. 최종 설치본·실제 복구 동작·검증 범위는 `web-image-recovery-evaluation-0.12.2.json`에 기록한다.

최종 설치본의 실제 복구 버튼 흐름에서도 새 공유 ID와 원본 NTK Figure 답변을 확인했다. 기존 대화 내부 오류는 계속 재현된다. 새 대화의 첫 이미지가 항상 한 번에 판독되는 것은 아니며, 사유 있는 재전송과 필요한 추가 영역 확대가 사용됐다. 세로축 표기의 모델 OCR 오독도 별도 기록했다. [최종 검증 기록](web-image-recovery-evaluation-0.12.2.json).

## 0.12.3 · 대화를 유지하며 이미지 읽기

기존 대화에서 이미지가 사라진 것으로 보였던 원인은 JavaScript 실행 래퍼의 결과 처리였다. 이 경로에서 content는 문자열이고, 실제 이미지 블록은 content_items에 들어 있었다. 일반 MCP의 content 배열 형태도 지원해야 한다. 두 배열 형태를 확인해 type:image 블록을 image(block) 또는 실행 도구의 동등한 이미지 출력 함수로 전달하도록 도구 설명·응답·질문 템플릿에 안내한다. JSON이나 메타데이터 출력만으로 픽셀을 읽었다고 판단하지 않는다.

**이미지 다시 읽기**는 기존 대화에 마지막 공유 질문의 후속 재확인을 요청한다. 이미지 원본 결과가 남아 있으면 먼저 표시하고, 없을 때만 같은 영역을 이유 있는 resend로 한 번 다시 받는다. 공유 ID와 PDF·질문·저장 옵션을 유지하며 새 대화로 이동하지 않는다. 브라우저에서는 **이미지 재확인 질문 복사** 후 기존 대화에 붙여넣는다. 이미 보이는 이미지 반복 전송은 여전히 참조만 반환하고 확대는 더 작은 region으로 한다.

이전에 실패했던 동일 대화에서 NTK Figure와 텍스트에 없는 검증 코드/색상까지 읽었다. 상세 기록은 [기존 대화 검증](existing-chat-image-evaluation-0.12.3.json)을 참조한다.
