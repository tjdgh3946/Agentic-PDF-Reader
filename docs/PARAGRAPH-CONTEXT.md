# 문단 검색과 필요한 문맥 확장 · 0.12.0 / MCP 0.3.0

ChatGPT 연결은 유지한다. 이 기능은 앞으로 전달하는 원문을 줄이며, ChatGPT 대화에 이미 들어간 도구 결과를 삭제하거나 context window 크기를 강제로 고정하지 않는다. 원본 PDF는 기존 공유 고정본에 보관하고 필요한 문단만 다시 읽는다.

## 검색 → 읽기 → 필요할 때 확장

1. `search_pdf({selectionId,query})`로 검색한다. 기본 3개/최대 5개 결과에 페이지·문단 ID와 최대 220자의 발췌를 반환한다. 검색어는 원문 언어의 FTS5 구문이다. 발췌는 완전한 근거가 아니므로 본문을 읽는다. 더 많은 결과가 있으면 `moreMatches=true`이며 검색어/페이지 범위를 좁힌다.
2. `read_pdf({selectionId,passageId,maxCharacters?})`로 해당 문단 원문을 읽는다. 기본 1,600자, 한 번에 최대 4,000 UTF-16 code unit이다. 원문과 일치하는 `start/end` 위치를 반환하며 잘린 UTF-16 surrogate pair는 반환하지 않는다.
3. `continuesAfter=true`이면 문단 뒷부분이 잘린 것이다. 결론/수식이 미완이면 `after` 커서를 `expand_pdf`에 전달해 남은 부분을 읽는다. 같은 문단이 끝나면 다음 커서가 다음 문단을 가리킨다. `paragraphComplete=false`는 이번 응답이 문단 일부라는 뜻이며, 마지막 연속 조각에서도 false일 수 있으므로 잘림 방향은 `continuesBefore/continuesAfter`로 판단한다.
4. 가정·정의·문장 주체가 앞에 있으면 `before`로 역방향 확장한다. 그림 해석에 캡션이 부족하면 캡션 방향을 읽는다. 커서는 직전 범위를 다시 포함하지 않는 인접 원문 범위를 가리키며 페이지 경계도 넘는다. 매 호출은 한 문단 또는 그 일부이며 예산 안에서만 반환한다.
5. 확장할 때는 `reason`에 무엇이 부족한지 180자 이내로 적는다. 충분한 근거를 확보하면 멈춘다. 단순히 커서가 있다는 이유로 계속 읽지 않는다. 먼 절의 정의나 정리는 새로 검색한다. 필요한 문단을 다시 읽는 것도 허용한다.

예: Theorem 2 검색 → 문단 앞 256자 읽기 → `continuesAfter=true`이므로 같은 문단의 나머지 확장 → 가정과 균등 수렴 결론이 모두 확인되면 정지. “학습 방향의 유계 조건이 현실적으로 언제 성립하는가?”라는 후속 질문이면 `before`로 직전 문단을 읽거나 least-squares 절을 새로 검색한다.

## 제한과 호환성

| 도구 | 기본 / 제한 |
|---|---|
| `search_pdf` | 3개 / 최대 5개, 발췌 각 220자 |
| `read_pdf`, `expand_pdf` | 본문 합계 1,600자 / 최대 4,000자, 최소 요청 128자 |
| `query_pdf` | JSON 행 합계 최대 4,000자, 셀 문자열 최대 3,000자, 20행/1.5초 |
| `render_pdf_page` | 기존 PNG 도구 유지, 위치를 알면 필요한 그림·캡션 영역을 지정 |

글자 수는 토큰 수가 아니다. 결과의 메타데이터도 문맥을 사용한다. 본문을 `content`와 `structuredContent`에 중복 복사하던 응답은 짧은 상태 문구 + `structuredContent` 한 곳의 자료로 변경했다. 기존 노트 조회 도구의 별도 길이 제한은 유지한다.

기존 `read_pdf({pages:[...]})` 호출은 유효하지만 이제 각 페이지의 **첫 문단만** 반환한다. 전체 페이지를 읽은 것으로 간주하면 안 된다. 합계 예산 때문에 반환하지 못한 페이지는 `omittedRequestedPages`, 텍스트 없는 페이지는 `emptyPages`에 명시한다. 기존 SQL 페이지 테이블은 유지하며 `paragraphs(passage_id,page_no,start,end,raw_text)`, `paragraph_fts(passage_id,page_no,text)`를 추가했다.

문단은 PDF.js의 줄 위치·간격·들여쓰기 및 빈 줄로 나눈 추정 단위다. 짧은 수식 조각은 인접한 본문에 묶는다. 원문 문자열은 재작성하지 않으며, 복잡한 다단 편집·표·수식의 순서가 부정확하면 인접 문맥 또는 페이지 이미지를 확인해야 한다. OCR은 추가하지 않았다.

모든 호출은 `selectionId`에 묶인다. 커서는 고정본 식별자와 원문 위치를 포함하며 다른 PDF에 적용할 수 없다. 앱 종료/공유 해제/만료 후 다시 공유해야 한다. 검색 발췌는 PDF를 읽었다는 근거로 저장하지 않고 실제 `read_pdf`·`expand_pdf`·이미지 읽기만 근거 이력에 반영한다.

ChatGPT 플러그인 **관리 → 도구 새로 고침**으로 `search_pdf`, `expand_pdf`를 포함한 11개 도구를 갱신한다. 새 질문 템플릿과 도구 지침이 이 흐름을 안내한다. 모델의 확장/정지 선택은 강제 횟수 제한이 아닌 지침이며, 서버는 각 응답의 크기와 공유 범위를 강제한다.

- `npx electron scripts/pdf-paragraph-check.mjs C:\Users\jsh\Downloads\1806.07572v4.pdf <report.json>`: 격리된 프로필에서 실제 PDF.js, SQLite, 공유 서버로 NTK 정리와 Figure 검색 및 확장 원문 일치를 확인한다.
- 실제 ChatGPT 및 설치본 결과는 `paragraph-context-evaluation-0.12.0.json`에 별도로 기록한다. API 비용/호스트의 실제 context token 감소를 측정한 것으로 해석하지 않는다.

실제 ChatGPT 시험에서는 Theorem 2의 최초 256자와 이어지는 263자만으로 정리 본문을 확인하고 멈췄다. 후속 질문에서 앞 문단 395자를 읽어 학습 방향의 해석을 보완했다. Figure 주제에서는 새로 검색해 903자의 관련 본문을 읽었지만 같은 전체 페이지 이미지를 3회 요청했다. 이미지 중복 억제는 이번 텍스트 예산 기능에 포함하지 않았으며 보고서에 남겼다.


## 0.14.1 · 이전 근거가 없을 때 재읽기

`delivery:reference`, `textRef`, `imageRef`는 이전 전달 기록이며 원문·픽셀이 아니다. 참조 응답에는 `contextRecovery`가 포함된다. `sourceIncluded`는 이번 응답에 일부 실제 원문이 포함됐는지를 표시하며, `missingReferences`의 범위는 여전히 빠져 있다. `retry.tool`과 `retry.arguments`는 같은 공유 ID·읽기 길이·문단/확장 커서 또는 이미지 페이지/영역을 유지한 실행 가능한 재요청이다.

모델은 정확한 이전 원문/픽셀을 현재 볼 수 있을 때만 재사용한다. 요약이나 기억만 있거나 접근 여부가 불확실하면 답하기 전에 `contextRecovery.retry`를 실행한다. 본문은 `reread:true`, 이미지는 `resend:true`와 구체적인 이유를 사용한다. 복구한 본문을 읽고 실제 이미지 블록을 표시해야 한다. 이번 복구 시도에서 근거당 한 번 재요청하고, 실패하거나 여전히 자료가 없으면 추측·반복·다른 공유 전환 없이 실패를 알린다. 확대는 별도 필요가 있을 때만 더 작은 영역으로 한다.

Reader는 ChatGPT 내부 압축 여부를 감지하거나 모델의 준수를 강제하지 못한다. 따라서 서버의 참조 응답·MCP 텍스트 안내·도구 설명·질문 템플릿 모두에 같은 규칙을 제공한다. 도구의 재읽기·재전송 자체는 이유가 없으면 거절한다. 실제 강제 context 압축 시험과, 이전 자료를 모델에 전달하지 않는 재현 시험은 구분해서 기록한다.
