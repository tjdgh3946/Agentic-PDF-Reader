# Paper Reader 안정성 테스트와 발전 방향

작성일: 2026-10-13 · 기준: Paper Reader 0.10.0 / Link 0.2.0.

이 문서는 다음 개발을 위한 제안과 완료 기준이다. 아래 체크되지 않은 항목은 앞으로 수행할 작업이며, 이번 문서 작성으로 구현하거나 검증을 완료한 것으로 취급하지 않는다. 실제 검증 이력은 [개발 인수인계](DEVELOPMENT-HANDOFF.md)와 두 평가 JSON에 남긴다.

## 제품의 중심

**읽던 위치에서 질문 → 논문 안에서 근거 탐색 → 답변과 원문 대조 → 원래 위치에 노트 저장**을 가장 짧고 믿을 수 있는 흐름으로 만든다. ChatGPT 모드가 기본이며, 별도 추론 사용량을 쓰는 앱 내 요청은 Plan B로 유지한다. 설정과 기능 수보다 창 전환, 복사·붙여넣기, 재인증, 근거 위치 찾기를 줄이는 것이 우선이다.

현재의 장점은 질문 당시 PDF를 고정하고 필요한 본문과 이미지만 도구로 읽게 하는 점이다. 텍스트는 검색·인용, 이미지는 수식·그림·레이아웃 확인에 사용한다. 여러 페이지라는 이유만으로 전부 텍스트나 이미지로 보내지 않고 질문에 필요한 자료를 단계적으로 읽는다.

| 항목 | 확인한 사실 | 남은 범위 |

## P0 — 다음 배포 전에 확인할 안정성

각 행은 자동 테스트가 이미 있어도 실제 EXE에서 추가로 확인할 시나리오다. 사용자 자료 대신 복사본·별도 테스트 프로필을 사용하고, 테스트 종료 후 변경한 설정을 복원한다.

| 영역 | 재현할 상황 | 통과 기준 |
| --- | --- | --- |
| 인증·재연결 | 정상 재실행, Windows 재부팅, 패키지 위치 변경, 잠자기·네트워크 단절 후 복귀 | 유효한 저장 키와 로그인 세션을 재사용한다. 복구 가능한 통신 오류 때문에 인증을 삭제하거나 키를 다시 요구하지 않는다. 실제 세션 만료·키 회수는 원인과 필요한 조치만 안내한다. |
| 중복 실행·업데이트 | Start-Link 두 번 실행, EXE 중복 실행, 구버전 실행 상태에서 새 버전 시작 | 사용 중인 앱·터널을 식별한다. 다른 프로세스를 무차별 종료하지 않고 버전·도구 목록 불일치를 안내한다. 정상 종료 뒤 불필요한 자식 프로세스가 남지 않는다. |
| 질문과 문서 일치 | A 논문을 질문한 뒤 B 열기, 색인 중 문서/질문 변경, 같은 파일명의 다른 PDF 열기 | 답변·검색·주석은 원래 고정본과 선택 ID를 따른다. 새 문서에 잘못 저장되는 사례가 0건이다. 취소·다시 공유가 필요한 상태는 명확히 알린다. |
| 공유 수명·권한 | 읽기/렌더 중 연결 해제, 24시간 만료, 노트 저장 불허 | 폐기된 공유의 진행 중 결과·쓰기까지 차단한다. 이미 저장한 노트는 유지하며, 저장 불허 시 새 노트가 생기지 않는다. |
| 전송의 확실성 | 더블클릭, Ctrl+Enter 반복, 기존 초안, 답변 생성 중, 전송 직후 네트워크 단절·페이지 이동 | 중복 질문·초안 덮어쓰기가 0건이다. 성공/미전송/결과 불확실을 구분한다. 불확실한 전송을 자동으로 다시 보내지 않는다. |
| 노트 내구성 | 저장·편집·삭제 후 재실행, 동일 저장 요청 반복, 저장 중 앱 종료, 쓰기 실패 | 성공 안내한 노트가 다시 열린다. 부분 기록을 정상 데이터로 오인하지 않고 복구 가능성을 안내한다. 중복 요청으로 노트가 늘지 않는다. |
| 하이라이트 좌표 | 다단·다중 페이지 선택, 반복 문장, 90/180/270도 회전, 배율·패널 폭·Windows 배율 변경 | 표시와 클릭 대상이 같은 원문을 가리킨다. 저장 후 재실행해도 일치한다. 스크린샷과 텍스트 앵커로 대조한다. |
| SQL·렌더 격리 | 금지 SQL, 긴 재귀 쿼리, 잘못된 페이지/crop, 작업 겹침, worker/renderer 강제 종료 | 파일 접근·쓰기를 막고 제한 시간 뒤 다음 정상 요청이 성공한다. PDF 스크롤·질문 입력이 멈추지 않는다. |
| 용량·문서 오류 | 64 MiB/1,000페이지/본문 1,200만 자 경계, 고정본 3개·합계 192 MiB 한도, 손상·암호화 PDF, 텍스트 없는 스캔 | 한도 초과·지원하지 않는 파일에 원인을 안내하고 기존 노트·열린 문서를 보호한다. 빈 본문을 논문에 근거가 없다는 뜻으로 처리하지 않는다. |
| 로컬 접근·비밀 정보 | 외부 Origin 요청, 위조 연결 파일, Markdown 원격 콘텐츠, 악성 PDF의 지시문 | 로컬 API 경계와 렌더링 제한이 유지된다. 자료 속 지시로 권한을 넓히지 않는다. 키·쿠키·연결 token이 UI/로그/ZIP/Git에 포함되지 않는다. |

인증 운용 원칙: 같은 Windows 계정에서는 저장소를 먼저 사용하고 매번 재입력을 요구하지 않는다. 키 교체와 삭제는 [연결 안내](../Paper-Reader-Link-연결안내.md)의 명시적 동작으로 제공한다. ChatGPT 로그인, 터널 인증, Paper Reader 로컬 공유 상태는 서로 구별해서 진단한다.

## 반복 가능한 검증 묶음

1. **변경에 맞는 자동 검증:** 좌표, 공유 수명, 저장, SQL 제한, 인증 저장 등 변경한 경계의 실패 사례를 검사한다. 배포 후보에서는 `npm test` 전체를 수행하고 소스 커밋·Node/Electron 버전을 기록한다.
2. **패키지 검증:** 그 커밋으로 EXE와 Link를 빌드한다. 실제 배포 패키지에서 7개 도구, 검색 worker, 페이지 PNG, 인증 재사용을 확인한다. 개발 소스만 통과한 결과를 EXE 결과로 대신하지 않는다.
3. **실제 내장 패널 왕복:** EXE에서 NTK 열기 → 문장/페이지 질문 → 현재 ChatGPT 대화 전송 → 검색/본문/이미지 → 노트 저장 → 원문 이동 → 앱 재실행을 확인한다. 최초 승인이나 로그인 만료는 사용자에게 넘기고, 정상 재실행에서는 불필요한 인증 입력이 없어야 한다.
4. **복구 시험:** 별도 테스트 환경에서 네트워크와 worker 종료를 제어하고 같은 질문의 중복 전송 없이 복구되는지 확인한다. 오류 뒤 새 질문이 성공해야 한다.
5. **장시간 시험 제안:** PDF 3종을 번갈아 열며 로컬 검색·렌더 50회, 열기/닫기 10회, 2시간 읽기를 수행한다. 이 숫자는 앞으로 적용할 시험량이다. 실제 ChatGPT 호출은 핵심 왕복 사례에 한정하고 대량 반복은 로컬 도구로 수행한다.

성능은 색인 시간, 첫 근거까지의 시간, 검색·렌더 p50/p95, 최대 메모리, 종료 뒤 잔류 프로세스를 같은 PC·PDF·cold/warm 조건으로 기록한다. 로컬 처리 시간과 ChatGPT 생성·네트워크 시간을 분리한다. 목표 수치는 대표 문서로 기준선을 측정한 뒤 정하며, 한 번의 따뜻한 캐시 결과를 제품 보장으로 쓰지 않는다.

테스트 자료에는 NTK 외에 2단 편집, 한글·영문 혼합, 스캔, 표·수식 위주, 회전·CropBox가 다른 페이지, 긴 PDF를 포함한다. 재배포 가능한 자료나 합성 fixture를 사용하고 사용자 PDF·대화·인증은 커밋하지 않는다.

## 검색·답변 품질 평가

- 질문마다 정답 문장뿐 아니라 필요한 페이지·그림, 정리의 가정, 답할 수 없는 범위를 작성한다. 새 논문 일부는 개발 중 보지 않은 평가용으로 남긴다.
- 한글 질문/영문 원문, 동의어, 합자·분리 부호, 숫자, 참고문헌이 첫 결과인 경우, 없는 전제를 포함한 질문, 여러 페이지 증명을 포함한다.
- 정해 둔 SQL 재생은 검색 엔진 회귀 검사다. 모델의 자율 검색 평가는 검색어와 순서를 미리 제공하지 않고 새 대화에서 수행한다. 후속 대화 재사용 실험은 별도로 기록한다.
- **근거 검색 적중, 인용이 주장에 실제로 부합하는지, 답변의 가정·수치 정확성, 이미지의 실제 호출 여부, 근거 부족을 인정하는지**를 각각 평가한다. 도구 성공률만으로 답변 품질을 판정하지 않는다.
- 이미지 질문은 축·범례·단위·곡선/표 셀을 원본 PNG와 대조한다. 모델이 그림을 봤다고 말하는 것과 서버가 이미지를 반환한 것을 함께 확인한다.
- 최소 진단 기록은 버전, 문서 fingerprint, 질문 사례 ID, 도구명·시간·상태·페이지·잘림 여부다. 현재 trace에 없는 이미지 영역/크기 등은 필요한 범위에서 추가한다. SQL이나 본문을 기록하는 상세 진단은 기본으로 켜지 않고 명시적으로 활성화·삭제할 수 있게 한다.

## 발전 방향과 완료 기준

| 순서 | 개선할 사용자 경험 | 구현 방향과 완료 기준 |
| --- | --- | --- |
| 1 | 답변 근거에서 원문으로 바로 돌아가기 | 현재 근거 페이지 버튼을 문장·수식·그림 위치로 발전시킨다. 문서 고정본/페이지/앵커를 가진 근거 참조를 노트와 함께 저장한다. 클릭하면 맞는 문서를 열고 위치를 강조하며 뒤로 돌아갈 수 있어야 한다. 텍스트의 임의 `p. N`을 검증 없이 정확한 인용으로 취급하지 않는다. |
| 2 | 연결과 질문 진행을 한눈에 이해하기 | 질문 단위로 공유 준비·전송·근거 탐색·답변·노트 저장 상태를 표시한다. 중복된 상태 문구와 설정 진입점을 정리하고 오른쪽 대화 공간을 우선한다. 인증·터널·앱·호스트 도구 갱신 중 어디가 막혔는지와 한 가지 다음 행동을 보여준다. 추정 사용량과 실제 제공된 사용량을 구별한다. |
| 3 | 수식·그림을 가리키며 질문하기 | PDF 위에서 영역을 선택하고 페이지·crop 미리보기와 함께 질문한다. 주변 캡션/정의는 텍스트로, 선택 영역은 PNG로 제공한다. 회전·배율 변경 뒤에도 같은 영역을 가리키고, 필요한 추가 페이지는 모델이 검색한다. 이미지 크기 선택은 가독성 평가로 결정한다. |
| 4 | 논문을 다시 열면 사고 흐름도 이어가기 | 논문별 질문·해결된 노트·미해결 질문·읽던 위치를 연결한다. 먼저 앱이 보유한 질문과 명시적으로 저장된 답변으로 구현한다. ChatGPT 대화 URL 연결은 사용자 선택으로 제공하고 실제 세션/대화 내용을 자동 동기화한다고 약속하지 않는다. |
| 5 | 여러 논문의 정의·가정·실험 비교 | 사용자가 고른 문서 집합을 명시적으로 공유하고 문서별 고정본과 인용을 유지한다. 비교표의 각 주장에 출처를 붙인다. 현재 3개/192 MiB 제한과 자원 회수 정책을 먼저 평가한다. 문서 간 주석 오저장 시험을 통과한 뒤 확장한다. |
| 6 | 검색이 어려운 자료까지 지원하기 | 스캔 OCR, 표·수식 영역 추출, 절/문단 단위 검색을 실패 사례로 평가한다. OCR 결과와 원본을 구별하고 오인식 교정 경로를 둔다. 임베딩 등 추가 검색은 현재 FTS+모델 재검색 대비 품질·시간·추가 비용을 측정한 뒤 채택한다. |

1번은 ChatGPT 답변 자체의 클릭 동작을 앱이 자유롭게 바꿀 수 있다는 가정을 두지 않는다. 우선 앱의 근거 목록·저장된 노트에서 정확한 이동을 완성하고, ChatGPT 쪽은 실제 호스트에서 지원·검증된 연결 방식으로 확장한다.

## 다음 개발 단위 제안

- [ ] **안정화:** P0의 인증·문서 전환·전송·저장·좌표를 EXE에서 재현하고, 실패 항목을 먼저 고친다. 내장 ChatGPT 왕복과 노트 재실행 복원까지 증거를 남긴다.
- [ ] **근거 이동:** 한 문서에서 문장/페이지/그림 근거 참조와 노트 이동을 구현한다. 사용자에게 보이는 클릭 횟수와 잘못된 이동 사례를 이전 버전과 비교한다.
- [ ] **영역 질문:** 그림·수식 선택 UI와 텍스트+PNG 전달을 추가하고 대표 과학 PDF로 검증한다.
- [ ] **읽기 재개:** 미해결 질문과 이전 노트를 쉽게 다시 찾도록 정리한다. 이후 다중 논문 비교로 확장한다.

배포를 막아야 할 실패는 문서가 바뀌어 잘못 저장되는 문제, 성공 표시 후 데이터 유실, 중복 전송, 해제된 공유 접근, 비밀 정보 노출, 복구되지 않는 멈춤이다. 그 밖의 발견 사항은 재현 절차·영향·우회 방법을 기록한다. 문서마다 `완료 / 실패 / 미검증`을 분리하고, 실제로 실행하지 않은 계획 항목은 완료 처리하지 않는다.
